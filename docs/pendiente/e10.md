- **Parser XML** (`bf-html/src/xml.rs`), lo que debe hacer un procesador no validante con el
  subset interno (XML §5.1):
  - Parameter entities internas: se guardan y sus referencias entre declaraciones se expanden
    como un frame (WFC: PE Between Declarations; recursión y límite de expansión como las
    generales).
  - Tras una referencia a una parameter entity que no se lee (externa o no declarada), las
    `ENTITY` y `ATTLIST` siguientes no se procesan; con `standalone="yes"` sí, y una entidad
    general o parameter no declarada es error (WFC: Entity Declared).
  - `ATTLIST` (§3.3): se parsea entero (`CDATA`, tipos tokenizados, enumeraciones,
    `NOTATION`, `#REQUIRED`/`#IMPLIED`/`#FIXED`); la primera definición de cada atributo
    manda. Los atributos omitidos con valor por defecto se agregan (después de los dados) y
    los tipos no `CDATA` colapsan espacios (§3.3.3). Se aplica antes de resolver namespaces:
    un `xmlns`/`xmlns:p` por defecto declara el namespace. Ningún `.xht`/`.xhtml`/`.svg`/`.xml`
    de `tests/wpt` usa `ATTLIST` ni parameter entities, así que los reftests no cambian.
  - `xml:space`, `xml:lang`, `xml:base`: quedan como atributos del namespace XML con prefijo
    `xml` (el whitespace no cambia; `xml:lang` lo usa `:lang()`; `xml:base` no cambia la base
    URL, HTML no lo soporta). Tests de que `xmlns:xml` solo acepta el namespace XML.
  - `parsererror` al navegar: `parse_xml_document_with_error_report` (nuevo, exportado):
    lo parseado hasta el error más un `parsererror` XHTML en línea, como Blink/WebKit
